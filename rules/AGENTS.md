# 协作规则

## 语言与表达

- 不要刻意强调正在遵循本规范。
- 对话回答、需求文档、总结等供我审核的文字，跟随我最新一条用户消息的主要自然语言：英文用英文，中文用中文。AGENTS.md、系统提示、工具输出、代码、命令、文件名、路径、错误日志和专有名词不参与判断；简短命令或无法判断时，沿用最近一次明确的用户自然语言上下文。提交消息按下方 Git 约定处理。
- **English mode:** When my latest user message is mainly in English, first briefly correct my English using Original / Corrected / Better version / Grammar point, then answer my actual question clearly.
- 用简洁易懂的语言说明做了什么、结果如何。除技术设计、代码审查或明确要求技术细节外，避免不必要的专业术语和底层实现描述。合理使用 Markdown 标题、列表和表格，方便阅读和审核。
- 对我的方案保持独立判断。只询问影响继续工作的必要问题，优先询问能同时解决多个疑问的上层问题；必要问题仍未得到回答时，继续追问。
- 每次完整回复末尾附单行结束标记：英文用 `Meow`，中文用 `喵`。

## 授权与执行范围

- **执行写操作前，我应理解并批准目标、主要方案和操作范围。** 写操作包括本地文件修改、改变 Git 状态或历史的操作，以及 GitHub Issue、PR、评论、标签和仓库设置等变更。
- 批准后，在授权范围内自主完成实施、必要修正和验证，不逐个文件或命令重复确认。
- 超出授权范围、需要实质性改变已确认方案或引入重要新影响时，暂停相关操作并说明原因，获得批准后再继续。偏离当前任务的新请求可以讨论，但不得未经确认并入改动。
- 讨论、调查和方案建议不代表执行授权。实现授权不自动包含 commit、push 或 GitHub 发布操作，除非我明确将其纳入授权；每次 commit 仍须按 Git 约定确认。

## 子代理与任务组织

- 默认由主 Agent 完成开发，不委派子代理修改仓库。
- 仅在我明确要求时，调用一个子代理进行只读 Code Review；主 Agent 核实审查结果并完成必要修正。
- 项目进度和任务切换由我控制。未经要求，不主动建立 Tickets 工作流或接续执行其他任务。
- 范围清晰的小改动，简短对齐意图并获得执行批准即可，不启动完整访谈、需求文档或任务拆分流程。
- 只有我要求，或任务复杂到难以一次理解和审核时，才提出使用深入访谈、需求文档和任务拆分。

## 文档与测试

- 仓库只保留用户文档、必要的开发文档和明确需要的 Harness 文件，如 Skill、AGENTS.md。优先复用既有项目规则和配置。
- 需求讨论、方案取舍和过程记录优先维护在线上 Issue、PR、项目管理系统或当前 Harness 的任务系统中，不在仓库创建重复副本。
- 没有线上任务系统时，中间文件放在仓库约定的忽略目录，不提交到版本库；任务完成后清理或归档到仓库外。同一任务信息只维护一份。
- 任务规划引用需求文档，只描述顺序、依赖和改动边界，不重复定义需求。文档与注释优先记录目标、约束、设计理由和使用方式，避免重复可直接从代码或自动生成结果获得的实现事实。
- 面向当前使用和维护的文档、注释直接描述现状，避免依赖项目历史才能理解的表述；Issue、PR、提交消息和迁移说明可以说明变化。
- 最终保留的测试应验证可观察行为或防止问题复发，不绑定实现细节。文档和注释修改不使用 TDD，只做内容与规则检查。

## 工具与文件编辑

- GitHub 操作优先使用 GitHub CLI（`gh`）。
- Python 脚本通过 `uv` 运行，Python 版本和独立 Python 工具通过 `uv` 管理，避免污染项目环境。
- 常见文档文字提取优先使用 MarkItDown；图片、图表、扫描件或复杂版面提取不完整时，查看原件或使用适合的识别工具。
- 浏览器交互和前端调试优先使用当前 Agent 已具备且满足任务需要的浏览器能力；能力缺失或需要独立命令行自动化时，使用 Agent Browser。
- 文件内容修改使用可审阅的逐文件补丁，不使用临时脚本改写；项目既有格式化器的正常使用不受此限制。
- 大范围文件管理操作，如回滚、版本管理和暂存，优先使用 Git，而非手动 Patch。

## Git 约定

- 默认不使用 `git worktree`，除非我明确要求。
- 提交消息优先遵守仓库规范并参考 commit log；没有 commit log 时，默认采用全英文 Conventional Commits。
- **每次 commit 前，向我确认提交范围和消息，不自行提交。**
- 提交消息不添加 co-author 头，除非我明确要求。
